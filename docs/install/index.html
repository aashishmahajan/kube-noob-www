Install kube-noob

kube-noob needs Python 3.11 or newer. macOS's built-in python3 (from the Xcode Command Line Tools) is 3.9, so a plain pip install there fails. Homebrew and uv bring their own Python (uv downloads one when yours is too old), and pipx installed with Homebrew uses Homebrew's.

Method Commands Upgrade
Homebrew (Apple silicon macOS, Linux) brew tap aashishmahajan/kube-noob https://github.com/aashishmahajan/kube-noob, then brew trust --formula aashishmahajan/kube-noob/kube-noob, then brew install kube-noob brew update && brew upgrade kube-noob
uv (downloads a Python if yours is too old) uv tool install kube-noob uv tool upgrade kube-noob
pipx pipx install kube-noob pipx upgrade kube-noob
pip, in a virtual environment python3.13 -m venv ~/.venvs/kube-noob, then ~/.venvs/kube-noob/bin/pip install kube-noob ~/.venvs/kube-noob/bin/pip install -U kube-noob
Container podman run --rm ghcr.io/aashishmahajan/kube-noob:0.7 --version pull the new tag
Claude Code plugin /plugin marketplace add aashishmahajan/kube-noob, then /plugin install kube-noob@kube-noob /plugin marketplace update kube-noob

The tap is needed because kube-noob is not in Homebrew's main catalogue; after brew tap, brew install kube-noob finds it. Homebrew 6 and later also refuse formulae from third-party taps until you trust them; brew trust --formula trusts only this one formula (Homebrew: Tap Trust). Get uv or pipx with brew install uv or brew install pipx.

Every method installs two commands: kube-noob and its short form noob (from 0.2.3). The PyPI package named noob is an unrelated graph library that also installs a noob command; if you have it, use kube-noob.

Check what you are running:

kube-noob --version
which -a kube-noob

which -a lists every kube-noob on your PATH. If it prints more than one, an older install is shadowing the new one: remove it with the tool that installed it (pipx uninstall kube-noob, uv tool uninstall kube-noob or brew uninstall kube-noob).

Agent Skill

The same tools as the MCP server, as an Agent Skill: a folder with SKILL.md, a runner (scripts/kn.py, one tool per call, JSON out) and the readable server source the Claude plugin ships. Use it where no MCP server runs: chat on claude.ai (the plugin's local MCP server runs in Claude Code and Cowork only) and the Claude API's code execution. It runs with the offline lock on and needs Python 3.11 or later with pydantic, PyYAML and jsonschema; kn.py check says which are missing.

Where Install
claude.ai (Pro, Max, Team, Enterprise, with code execution on) Download kube-noob-skill-<version>.zip from the GitHub release (from 0.7.0), then upload it under Customize > Skills and turn it on
Claude Code Unzip it into ~/.claude/skills/ (so the file is ~/.claude/skills/kube-noob/SKILL.md), or install the plugin instead, which also gives the MCP tools
From a checkout python scripts/build_skill.py --zip kube-noob-skill.zip or --out ~/.claude/skills/kube-noob

Run it yourself to see what Claude sees:

python3 -I -B kube-noob/scripts/kn.py check
python3 -I -B kube-noob/scripts/kn.py tools
python3 -I -B kube-noob/scripts/kn.py insight '{"text": "0/3 nodes are available: 3 Insufficient memory"}'
python3 -I -B kube-noob/scripts/kn.py audit_manifests --text-file manifests=app.yaml

error: externally-managed-environment Homebrew's or the system's Python refuses packages installed into it (PEP 668) Use pipx, uv or a virtual environment; do not add --break-system-packages
zsh: command not found: pip macOS has no pip command, only pip3 Use pipx or uv, or python3 -m pip inside a virtual environment
command not found: kube-noob after pipx or uv Their bin folder is not on your PATH yet pipx ensurepath or uv tool update-shell, then open a new terminal
