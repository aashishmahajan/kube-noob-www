Privacy

kube-noob is open-source software that you run yourself: on your computer, in your CI, or in your cluster. The maintainers run no service for it and receive nothing from it. There are no accounts, no telemetry and no analytics. The website's contact and license forms are the one place the maintainer receives data: see The website.

There is no AI inside kube-noob. When you use it from Claude, OpenShift Lightspeed or another MCP client, that client and its model do the talking and call kube-noob's tools. What you share in that conversation is handled by that product under its own terms and privacy policy. kube-noob adds no network traffic of its own.

What it reads

  • Text you give it: manifests, events, logs, error messages and questions. It processes them in memory to answer; names it finds there (a pod, a Service, a label selector, a namespace) go only into the steps it prints.
  • Its bundled knowledge, and documents you index yourself with kube-noob corpus add-docs.
  • Only if you turn on cluster access: read-only requests to the Kubernetes or OpenShift API of your current kubeconfig context. It never reads Secrets and redacts values that look like credentials.

What it stores, on your machine only

Everything lives in the data directory: ~/.local/share/kube-noob by default, or KUBE_NOOB_DATA_DIR.

Nothing from a request is kept after it is answered. What is listed above stays until you delete it; the maintainers never receive it.

kube-noob must-gather analyze --report DIR writes report.md, report.json and, with --case-draft, case-draft.md to the folder you name; they hold redacted findings from the must-gather, never its Secrets, and nothing is sent anywhere. kube-noob bundle writes a redacted evidence pack to the folder you name (default ./kube-noob-bundle). The MCP server's log line records each tool name, argument sizes and duration, never argument contents.

What it sends, and where

By default, nothing. Each destination below is off until you turn it on.

Allowlisted documentation sites (listed below) webEnabled: true; refused under the offline lock HTTPS GET of the page address; nothing is downloaded to disk or run
The model you configure Only kube-noob ask, kube-noob train bench and the eval judge Your question and the tool results; under the offline lock, local models only
The GitHub Actions API (ci.githubApiUrl, default api.github.com) ci.githubEnabled: true; only kube-noob build history; under the offline lock only an in-cluster *.svc host HTTPS GET of the repository's workflow runs, their attempts and jobs, with your token; the runs are written to the folder you name
Nowhere: the admission webhook (kube-noob admission serve, chart admission.enabled) Running it It receives the objects your API server sends it (never Secrets or ConfigMaps), answers with warnings or a denial, keeps only request counts and latencies, and sends nothing; admission.lookups adds read-only lists of five kinds from your API server, as in the row above

Red Hat's security data (security.access.redhat.com) Only kube-noob corpus advisories --online; refused under the offline lock (--from-archive reads a downloaded file instead) HTTPS GET of changes.csv and the VEX document of each CVE, one request a second plus jitter, within --max-requests; nothing about you
Public GitHub repositories and the public Red Hat Jira Only kube-noob corpus build, jira, jira-projects, history and known-issues, and jira.sync.enabled in the service; refused under the offline lock Requests for public data: Jira search queries (project key, an "updated in the last N minutes" or "key below N" filter) through its REST API, at most one per second

The default web allowlist is kubernetes.io, helm.sh, docs.redhat.com, docs.openshift.com, access.redhat.com, cloud.redhat.com, developers.redhat.com, redhat.atlassian.net, docs.aws.amazon.com, github.com, raw.githubusercontent.com, stackrox.io, www.stackrox.io, gateway-api.sigs.k8s.io and kind.sigs.k8s.io, with their subdomains. You can shorten or replace it with web.allowedDomains.

kube-noob doctor prints what the running process can reach. Administrators can set offline: true (or KUBE_NOOB_OFFLINE=1) to block web access and downloads and to allow only local models; nothing later in the configuration can lift it.

The Claude plugin

The plugin starts the bundled server on your computer over stdio, with web access, cluster access and model calls off. Its Python dependencies are installed from PyPI at the versions and hashes in the plugin's uv.lock, into a throwaway environment in uv's cache (and uv's managed CPython once, if no Python 3.11 or later is installed). The plugin ships only the modules of the stdio server: no CLI, model agent, HTTP service, web client or cluster access, so it reads no credentials and makes no network calls of its own. Personal data is never requested. If text you paste contains some, it is processed in memory and not stored, except words you choose to put in a confirmed note or a learner id.

The Agent Skill

The skill runs where Claude runs code: your computer in Claude Code, a sandbox for chat on claude.ai. It reads only the files named in a call, makes no network connections (web, cluster and model are forced off) and sends nothing to the maintainer. Like the server, it keeps learning progress and notes you confirm in kube-noob's data folder (KUBE_NOOB_DATA_DIR, else ~/.local/share/kube-noob) inside that environment; a claude.ai sandbox discards them when it ends.

The website (kube-noob.com)

A static site on GitHub Pages, built from this repository's releases. It sets no cookies, runs no analytics and loads its pages, scripts and fonts from its own host only. GitHub Pages, which serves it, keeps its own access logs under GitHub's privacy statement. Data leaves your browser in three cases, and only when you act:

  • Contact, feedback and student-license forms. When you submit one, what you typed goes to a Google Apps Script web app the maintainer runs, which stores it in the maintainer's private Google Sheet and emails the maintainer a copy. A message keeps its time, topic or area, rating, your name, email address, text and the page it was sent from. A student license keeps its id, your name, email address and school, and that you said you are a student; the license id is emailed to you. The data is used only to reply to you or to keep your student record, is not sold or shared, and is deleted on request through the contact form.
  • Bring your own AI. That page sends your Anthropic API key and your messages from your browser straight to api.anthropic.com, under Anthropic's terms for your key; the site never receives them. The key is kept in memory, or in the tab's session storage only if you tick the box.
  • Playground. It runs kube-noob's tools in your browser: what you paste stays on your device.
