Safety contract

Generated by scripts/safety_contract.py from the code. Do not edit it: python scripts/safety_contract.py rewrites it, python scripts/safety_contract.py --check (part of scripts/check.sh) and tests/test_safety_contract.py fail when it no longer matches the code, and the script refuses to write it while any invariant below is violated.

Invariants (checked on every run and by the tests)

Invariant Holds Derived from
No tool without a capability tier is read_only=False, except the named local-state writers below yes Toolkit.specs(), kube_noob.tiers

No exec, attach, portforward or proxy subresource is reachable: not in the backend, in no chart Role yes backend, chart templates

Every subprocess is an argv list, none uses a shell, and a new call site needs review yes syntax tree of src/kube_noob
Every MCP tool result and the knowledge resource pass through the sanitiser; each kind it reports is demonstrated yes server/mcp_app.py, sanitize.py

There are 57 tools in all. 50 are read-only. 7 are not read-only and have no tier, and they write only this machine's own state (below). No tool has a tier: every capability tier beyond reading (probe P, dry-run D, external writes W, gate G) exists as configuration and optional RBAC, and none is exposed as an MCP tool.

Live cluster access (tier R)

Off until cluster.enabled is true. The backends are KubectlBackend (runs kubectl or oc with the operator's kubeconfig) and InClusterBackend (HTTPS to the API server with the pod's ServiceAccount token); the Claude plugin ships without them.

  • kubectl subcommands the backend runs: get, logs, version
  • HTTP methods the in-cluster backend sends: GET
  • Verbs the API server is asked for: get, list (watch is never requested: no --watch, no watch=true)
  • Flags it can pass: --all-namespaces, --container, --context, --field-selector, --namespace, --output, --previous, --request-timeout, --selector, --tail
  • API paths it builds: /api/v1, /api/v1/namespaces/, /api/v1/namespaces/{namespace}/pods/{pod}/log, /apis/, /apis/{self.group_version}, /version
  • Names, namespaces, selectors and containers taken from a caller must match strict patterns (_NAME, _SELECTOR, _FIELD_SELECTOR, _CONTAINER in debug/cluster.py), none of which admits /, ?, # or a newline, so a name cannot add a path segment such as /exec or /proxy.
  • resolve_resource refuses secrets by name and any resource outside the allowlist below (37 resources, 53 short names); subresources such as pods/exec are not in it.
  • Output is redacted before it leaves the backend: 10 credential patterns for logs and text (markers ***JWT***, ***PRIVATE KEY***, ***aws-key-id***, ***github-token***, ***slack-token***, ***vault-token*** and *** for values), ConfigMap data and binaryData replaced by byte counts, sensitive env values, last-applied-configuration and sensitive annotations masked, managedFields dropped.

Prompt-injection handling of MCP results

kube-noob calls no model, but the model that calls kube-noob reads its results, so text that came from outside (events, logs, tickets, memory entries, pages) is cleaned before a result leaves the server. The sanitiser is kube_noob.sanitize; it is defence in depth, not a guarantee.

Where it is applied (found in the code):

  • kube_noob/evals/problems.py parse calls sanitize.json_nesting_ok
  • kube_noob/insight.py _json calls sanitize.json_nesting_ok
  • kube_noob/server/mcp_app.py CallFailed.__init__ calls sanitize.clean
  • kube_noob/server/mcp_app.py build_server.knowledge_doc calls sanitize.clean
  • kube_noob/server/rest.py register.endpoint.handle calls sanitize.json_nesting_ok
  • kube_noob/signals/alertmanager.py _load calls sanitize.json_nesting_ok
  • kube_noob/tool_runner.py call calls sanitize.result

Finding kinds it reports (read from its source): bidi-override, instruction, instruction-hint, markdown-image, markdown-link, role-marker, tool-call, unicode-tags, zero-width.

A result that had any finding carries untrusted: true and injectionSignals (at most 20, with an excerpt that cannot carry the instruction back). Limits: 4,000,000 characters scanned per string, nesting depth 40, 20 base64 runs decoded per string. Matching runs on a normalised copy (compatibility forms folded, look-alike letters mapped, entities and colour codes decoded, format characters and hyphenated line breaks removed, white space collapsed) and is mapped back to the original text.

What this does not prove

  • It reads this repository. It does not see the RBAC your cluster admin binds to a kubeconfig that kubectl or oc uses.
  • The chart's Roles are what the chart creates. A cluster can bind other roles to the same ServiceAccount.
  • The sanitiser is defence in depth against text that tries to steer the calling model; the model's own handling of tool results still matters.
  • Tier D and tier P Roles grant create, patch and delete by design; kube-noob asks a person to approve every such action, and its audit rule KN-S017 flags those permissions when they appear in a manifest.
