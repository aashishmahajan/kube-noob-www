Product journey

From a broken pod to a cited, read-only fix

kube-noob is the rulebook, not the chatbot. Below is what it does, step by step, with the real output of kube-noob demo from this build: offline, in under a second, never touching a cluster.

The 7-step protocol

Every design request runs these steps, in this order.

  1. Clarifyplatform/version inference (blueprint > explicit > request text > manifest API groups), blocking questions vs stated assumptions.
  2. Validatestrict JSON schema (Kubernetes 1.35 + CRDs), apiVersion/kind catalog, removed APIs per target version, selector/port wiring.
  3. ResearchBM25 over local knowledge; results carry chunk ids, source URLs and licenses.
  4. Auditsecurity, RBAC, network exposure, storage access modes vs provisioner capabilities.
  5. Calibrateprobes, resources, replicas, PDBs, topology spread, HPA prerequisites.
  6. Generatedeterministic generator (blueprints) or mechanical fixer (existing YAML) with a change log.
  7. Red Teamnine adversarial scenarios evaluated on the final output; remaining HIGH/CRITICAL findings mark the result blocked.

What it does, in real output

Audit and auto-fix a Deployment for OpenShift

For: developers, platform engineers

Paste a Deployment and get findings with the line, the fix, the RHACS policy and the NIST controls; fix applies the safe mechanical changes and audits the result again.

kube-noob demo audit

== kube-noob demo: Audit and auto-fix a Deployment for OpenShift ==

# Audit a Deployment that works on a laptop but not on OpenShift
$ kube-noob audit -f examples/insecure-deployment.yaml --platform openshift --version 4.22
score 37.0/100 | high=3 medium=7 low=5
[HIGH    ] KN-S013 line 23: Container 'api' sets DB_PASSWORD as a literal value.
    fix: Move the value to a Secret and reference it with valueFrom.secretKeyRef (or an external
      secret store).
[HIGH    ] KN-S004 line 25: Container 'api' sets runAsUser: 1000; restricted-v2 will reject IDs outside the namespace range.
    fix: Remove runAsUser/fsGroup and let OpenShift assign IDs from the namespace range; keep
      runAsNonRoot: true. If a fixed UID is truly required, bind the ServiceAccount to the
      nonroot-v2 SCC. (runAsGroup is not governed by SCCs and is left alone.)
[HIGH    ] KN-S002 line 26: Container 'api' explicitly allows privilege escalation.
    fix: Set securityContext.allowPrivilegeEscalation: false on every container.

# Apply the safe mechanical fixes and re-audit
$ kube-noob fix -f examples/insecure-deployment.yaml --platform openshift -o fixed.yaml
5 changes applied; score 37.0 -> 59.0
  + spec.template.spec.securityContext.seccompProfile: Pod Security restricted requires RuntimeDefault seccomp.
  + spec.template.spec.securityContext.runAsNonRoot: Refuse to start as root.
  + spec.template.spec.containers[0].securityContext.runAsUser: restricted-v2 assigns IDs from the namespace range.
  + spec.template.spec.containers[0].securityContext.allowPrivilegeEscalation: restricted-v2 rejects allowPrivilegeEscalation: true, so the pod could not start anyway.
Left for a human (needs app knowledge):
  - Deployment/shop/orders-api: runAsNonRoot: true was added. Images whose USER is root will now
    fail with CreateContainerConfigError ('container has runAsNonRoot and image will run as root');
    use an unprivileged image variant or set a numeric non-root USER in the Dockerfile.
  - Deployment/shop/orders-api container 'api': consider readOnlyRootFilesystem: true with emptyDir
    mounts for writable paths (needs app knowledge).

Diagnose SCC and CrashLoop/OOM failures, read-only first

For: SREs, on-call

Paste events or logs and get the likely cause, then read-only steps first. Commands that run inside a container or change the cluster come last, marked as needing approval.

kube-noob demo diagnose

== kube-noob demo: Diagnose SCC and CrashLoop/OOM failures, read-only first ==

# Pods are never created: paste the events
$ kube-noob diagnose -f examples/events-scc.txt
DBG-SCC: Pod rejected by SecurityContextConstraints (confidence 1.0)
  1. read-only first:
     oc get events -n shop --field-selector reason=FailedCreate
     oc describe rs -n shop -l <app-label>
       why: FailedCreate message lists every SCC tried
     oc get ns shop -o jsonpath='{.metadata.annotations.openshift\.io/sa\.scc\.uid-range}'
  2. change, only after the evidence (asks before running):
     Remove runAsUser/runAsGroup/fsGroup and keep runAsNonRoot: true (preferred).

# A pod keeps restarting: paste `oc describe pod`
$ kube-noob diagnose -f examples/events-crashloop.txt
DBG-OOM: Container killed for exceeding memory (OOMKilled / exit 137) (confidence 1.0)
  1. read-only first:
     kubectl describe pod orders-api-7c4b9d6f5-x2lqp -n shop
       why: Last State: Terminated, Reason: OOMKilled
     kubectl top pod orders-api-7c4b9d6f5-x2lqp -n shop --containers
     kubectl get events -A --field-selector reason=OOMKilling
  2. change, only after the evidence (asks before running):
     Set limits from observed p99 usage plus headroom; keep requests ~= steady-state usage.

passed: False | score 0.4 | points 6

    securityContext.allowPrivilegeEscalation: false on every container.

    NetworkPolicy plus explicit allows (router/ingress controller, monitoring, same-app traffic).

How it got here

Every release, newest first, from the changelog.

0.7.1

2026-10-31

**Two holes in the Jira corpus scrubber let person-shaped text reach stored tickets**, which is what the `corpus-refresh` privacy gate has been refusing since 2026-10-28 with 123 findings. `_ACCOUNT` required the id to start within one punctuation character of `accountId`, so the JSON spelling `{"accountId": "5b10..."}` -- quote, colon, space -- kept a real Atlassian account id. And `scrub()` ran before `unname()`, so a display name it could not recognise as a person (a non-ASCII one is neither email- nor handle-shaped) survived the scrub and was only then swapped for its label, leaving text like "ping Commenter A at quay.io" that reads as a spelled-out email. `anonymise()` now runs the chain in an order that holds -- scrub, unname, handles, scrub again -- and the widened `_ACCOUNT` accepts any mix of quote, colon, equals and space before the id. The audit that gates the corpus is deliberately not loosened: it may still over-flag a bare 24-character hex string that is not an account id, and telling those apart needs the real tickets.

0.7.0

2026-10-30

Plugin and catalog readiness (independent review against the directory's and the OpenShift Helm charts repository's requirements): the Claude plugin no longer ships the HTTP client, the REST routes or Helm rendering (`kube_noob.generate.helm_render`, the only `subprocess` call), so nothing in it can open a connection or start a program; `web_fetch` is offered only where the network module ships. The Agent Skill drops `httpx` from what it needs. `plugin.json` carries the directory listing links (documentation, support, privacy policy) and says the plugin makes no network calls of its own while uv installs its pinned dependencies once; `claude plugin validate` passes with nothing to report.

0.6.0

2026-10-29

New documents for the weakest technologies in the owner's by-technology file, written from each project's own docs by writers that never saw the test half, every claim checked against the cited lines: Helm template functions (`range`, `toYaml` and `nindent`, `default` and `required`, `tpl`, `.Files`, `lookup`, subchart values), Gatekeeper usage (Rego in ConstraintTemplates, audit results, `spec.match`, ExpansionTemplate for workloads, install on OpenShift) and kubectl output and scripting (jsonpath, custom-columns, `--sort-by`, `--field-selector`, logs, `wait`, `exec`, `diff`). Four more drafts are held back because blinded graders on real posts found them worse more often than better: Rook-Ceph operations, Rook-Ceph troubleshooting, Jobs/CronJobs and kustomize, and Kyverno usage. In a long pasted post (over 300 characters), the words that name a document's subject ("gatekeeper", "rego", "helm", "chart") no longer count toward the words the document must share with the post, because every post about that subject shares them. A typed question or a short post still counts every word. Measured on the owner's two answered files with two blinded graders per row: - the subject rule on the train half: 69 and 61 answers better, 25 and 25 worse; - the shipped change against the previous answers on the test half, every changed row not used for a decision (122): 54 and 53 better, 31 and 27 worse. The 132 test rows that decided which drafts ship are retired. - Reported-issue answers fell from 523 to 515, because the new documents explain words that had looked rare. - Golden: unchanged in scope (89 of 96); out of scope 22 of 23 (rosa-019 now abstains).

First release. - MCP server (stdio + authenticated streamable HTTP), CLI, Claude plugin with 7 skills, Helm chart and sidecar example. - 7-step protocol (Clarify, Validate, Research, Audit, Calibrate, Generate, Red Team). - 60 deterministic audit rules plus strict schema validation (Kubernetes 1.35, Route, SCC, EgressFirewall, Gateway API, StackRox CRDs), 9 red-team scenarios, safe auto-fix, RHACS policy mapping. - Generator for kubernetes / openshift / rosa-classic / rosa-hcp manifests and Helm charts. - 33 debugging playbooks and read-only live cluster evidence (kubectl/oc or in-cluster ServiceAccount). - 28 fact-checked knowledge docs (OCP 4.22 = Kubernetes 1.35, Helm 4, RHACS 4.11 -> 5.0, ROSA HCP architecture). - Learning tracks with graded exercises, quizzes and credits. - Corpus builder (Git docs with license provenance, release history, jittered Jira pulls), deterministic reward with TRL adapter, held-out benchmark, SFT/GRPO export. - Hardened before release after an independent red-team review: assertion-gated, negation-aware reward with citation relevance; config never read implicitly from the working directory; LLM key/endpoint restrictions; redaction of credentials in every cluster string; duplicate-key and nesting-depth checks; fixer output that the API server accepts (privileged containers, root containers, null securityContexts, duplicate EgressFirewalls).
