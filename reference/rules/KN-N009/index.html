Audit rules / KN-N009

KN-N009 Ingress uses a risky ingress-nginx annotation

high · audit / network

What it finds

ingress-nginx turns some annotation values into nginx configuration. Its annotation risk list rates the five snippet annotations Critical (raw configuration) and ten more High; these annotations carried the published injection CVEs: CVE-2021-25742 (snippets read every Secret in the cluster), CVE-2021-25746 (directive injection through annotation values), CVE-2023-5043 and CVE-2023-5044 (configuration-snippet, permanent-redirect), CVE-2025-24514, CVE-2025-1097 and CVE-2025-1098 (auth-url, auth-tls-match-cn, mirror-target and mirror-host), CVE-2025-15566 (auth-proxy-set-headers), CVE-2026-1580 (auth-method), CVE-2026-24513 (auth-url) and CVE-2026-3288 (rewrite-target). Through the snippets, CVE-2021-25742 obtained all Secrets in the cluster from an Ingress alone.

How to fix it

Remove the annotation (move the behaviour into the application or the controller's own configuration); if it must stay, run a fixed controller release with --enable-annotation-validation, keep allow-snippet-annotations false and annotations-risk-level at High or below in the controller ConfigMap, and plan the move to a Gateway API implementation, since ingress-nginx is retired.
