Audit rules

77 rules. Rule ids are a public contract: they never change meaning or get renumbered. Each names the NIST SP 800-53 Rev. 5 controls it is evidence about and the RHACS (StackRox) policies that would fire. Try them on your YAML in the playground.

IdRuleSeverityStage / categoryNIST controlsRHACS policies
KN-C001No readiness probe
Without readiness, Services route to pods that are still starting or degraded, and rollouts cannot detect bad versions.
Fix: Add a readinessProbe (httpGet on a /ready endpoint, or tcpSocket) so traffic only reaches ready pods.		mediumcalibrate / reliabilityCP-10 System Recovery and Reconstitution
KN-C002No liveness probe
Deadlocked processes are never restarted without liveness.
Fix: Add a livenessProbe that checks the process itself (not its dependencies); use a startupProbe for slow starts.		lowcalibrate / reliabilityCP-10 System Recovery and Reconstitution
KN-C003Liveness probe is aggressive
Aggressive liveness turns a slow dependency or GC pause into a restart storm (red-team: cascading failure).
Fix: Use periodSeconds >= 10, failureThreshold >= 3 and timeoutSeconds < periodSeconds; add a startupProbe for slow boots.		mediumcalibrate / reliabilityCP-10 System Recovery and Reconstitution, SC-5 Denial-of-service Protection
KN-C004Missing CPU/memory requests
Without requests the scheduler overcommits nodes, pods get BestEffort QoS and are evicted first; HPA cannot compute utilization.
Fix: Set resources.requests.cpu and resources.requests.memory from observed usage (p95).		mediumcalibrate / resourcesSC-6 Resource AvailabilityNo CPU request or memory limit specified
KN-C005Missing memory limit
An unbounded container can exhaust node memory and trigger node-level OOM kills of other workloads.
Fix: Set resources.limits.memory (typically 1-2x the request).		mediumcalibrate / resourcesSC-5 Denial-of-service Protection, SC-6 Resource AvailabilityNo CPU request or memory limit specified
KN-C006Request exceeds limit
The API server rejects containers whose request is greater than the limit.
Fix: Make every request <= its limit.		highvalidate / resourcesCM-6 Configuration Settings
KN-C007Single replica
One replica means downtime on every node drain, upgrade or node failure.
Fix: Run at least 2 replicas (3 across zones for production) with a PodDisruptionBudget.		mediumcalibrate / availabilityCP-10 System Recovery and Reconstitution, SC-36 Distributed Processing and Storage
KN-C008No PodDisruptionBudget
Without a PDB a node drain may evict all replicas at once.
Fix: Add a PodDisruptionBudget with maxUnavailable: 1 for replicated workloads.		lowcalibrate / availabilityCP-10 System Recovery and Reconstitution
KN-C009PodDisruptionBudget blocks all voluntary evictions
A PDB that allows zero disruptions blocks node drains, so cluster upgrades (including managed ROSA upgrades) stall on this node.
Fix: Use maxUnavailable: 1 (or minAvailable < replicas).		highcalibrate / availabilitySI-2 Flaw Remediation, CP-10 System Recovery and Reconstitution
KN-C010Replicas not spread across zones/nodes
Replicas may all land on one node or zone; a single failure takes the app down.
Fix: Add topologySpreadConstraints on topology.kubernetes.io/zone (and kubernetes.io/hostname) or pod anti-affinity.		lowcalibrate / availabilitySC-36 Distributed Processing and Storage
KN-C011terminationGracePeriodSeconds is 0
A zero grace period kills in-flight requests and can corrupt state.
Fix: Allow time for graceful shutdown (default 30s) and handle SIGTERM.		lowcalibrate / reliabilityCP-10 System Recovery and Reconstitution
KN-C012HPA cannot compute CPU utilization
Utilization-based HPA divides usage by the request; missing requests leave the HPA at <unknown>.
Fix: Set CPU requests on every container of the target workload.		mediumcalibrate / resourcesSC-6 Resource Availability
KN-C013Pull secret exists only in another namespace
imagePullSecrets name Secrets in the pod's own namespace (LocalObjectReference): kubelet never looks in another namespace, reports FailedToRetrieveImagePullSecret and the pull fails with ImagePullBackOff.
Fix: Create (or sync) the pull secret in the workload's namespace and link it to its ServiceAccount; on OpenShift put a registry every project uses in the global pull secret, and grant system:image-puller for another project's internal registry.		highvalidate / reliabilityCM-6 Configuration Settings
KN-C014Workload scaled by an HPA also sets spec.replicas
The Kubernetes docs recommend removing spec.replicas when an HPA is enabled: otherwise every kubectl apply (or GitOps sync) of the manifest scales the workload back to that number, which may not be desired and causes thrashing or flapping while the HPA is active, for example down to 2 replicas in the middle of a traffic peak. A target whose replica count is 0 deactivates an HPA whose minReplicas is above 0.
Fix: Remove spec.replicas from the manifest of a workload a HorizontalPodAutoscaler scales (in a Helm chart: {{- if not .Values.autoscaling.enabled }} replicas: ... {{- end }}); set the floor with the HPA's minReplicas.		mediumcalibrate / availabilityCM-6 Configuration Settings, SC-6 Resource Availability
KN-N001Namespace has workloads but no NetworkPolicy
Without NetworkPolicy every pod in the cluster can reach these pods (lateral movement).
Fix: Add a default-deny ingress NetworkPolicy plus explicit allows (router/ingress controller, monitoring, same-app traffic).		mediumaudit / networkSC-7 Boundary Protection, SC-7(5) Boundary Protection | Deny by Default — Allow by Exception, AC-4 Information Flow EnforcementDeployments should have at least one ingress Network Policy
KN-N002Route without TLS
Plain-HTTP Routes expose credentials and session cookies to anyone on the path.
Fix: Add spec.tls with termination: edge (or reencrypt/passthrough) and insecureEdgeTerminationPolicy: Redirect.		highaudit / networkSC-8 Transmission Confidentiality and Integrity, SC-8(1) Transmission Confidentiality and Integrity | Cryptographic Protection
KN-N003Ingress without TLS
Plain-HTTP ingress exposes traffic in transit.
Fix: Add spec.tls with a certificate Secret (cert-manager can issue it).		mediumaudit / networkSC-8 Transmission Confidentiality and Integrity, SC-8(1) Transmission Confidentiality and Integrity | Cryptographic Protection
KN-N004LoadBalancer Service open to the internet
A public cloud load balancer without source ranges is reachable from anywhere.
Fix: Set spec.loadBalancerSourceRanges, or make it internal (on AWS/ROSA: annotation service.beta.kubernetes.io/aws-load-balancer-internal: "true"), or front it with a Route/Ingress.		mediumaudit / networkSC-7 Boundary Protection, AC-4 Information Flow EnforcementDeployments with externally exposed endpoints
KN-N005NodePort Service
NodePorts widen the attack surface.
Fix: Prefer ClusterIP + Route/Ingress; NodePorts open a port on every node.		lowaudit / networkSC-7 Boundary Protection, CM-7 Least Functionality
KN-N006EgressFirewall rule is shadowed
EgressFirewall rules are evaluated in order and the first match wins, so an early catch-all Deny makes every later Allow dead code.
Fix: Put specific Allow rules first and the catch-all Deny 0.0.0.0/0 last.		highaudit / networkSC-7 Boundary Protection, SC-7(5) Boundary Protection | Deny by Default — Allow by Exception, AC-4 Information Flow Enforcement
KN-N007NetworkPolicy allows all ingress
An ingress rule of {} admits traffic from every pod and every external source.
Fix: Restrict 'from' to specific namespaceSelector/podSelector peers and ports.		mediumaudit / networkSC-7 Boundary Protection, SC-7(5) Boundary Protection | Deny by Default — Allow by Exception, AC-4 Information Flow Enforcement
KN-N008Service uses externalIPs
CVE-2020-8554 (every Kubernetes version; the Kubernetes CVE feed says there is no patch, the flaw is in the design): anyone who can create or update a Service can set externalIPs to any address and so intercept cluster traffic meant for that address (man in the middle). The Kubernetes docs describe the feature as very powerful (it allows network traffic interception), say most users do not need it, and recommend the DenyServiceExternalIPs admission controller, which rejects all net-new use of the field.
Fix: Remove spec.externalIPs and publish the Service through a LoadBalancer Service, a Route or an Ingress; enable the DenyServiceExternalIPs admission controller on the API server (on a managed platform, ask the provider).		highaudit / networkSC-7 Boundary Protection, SC-8 Transmission Confidentiality and Integrity, AC-4 Information Flow Enforcement
KN-N009Ingress uses a risky ingress-nginx annotation
ingress-nginx turns some annotation values into nginx configuration. Its annotation risk list rates the five snippet annotations Critical (raw configuration) and ten more High; these annotations carried the published injection CVEs: CVE-2021-25742 (snippets read every Secret in the cluster), CVE-2021-25746 (directive injection through annotation values), CVE-2023-5043 and CVE-2023-5044 (configuration-snippet, permanent-redirect), CVE-2025-24514, CVE-2025-1097 and CVE-2025-1098 (auth-url, auth-tls-match-cn, mirror-target and mirror-host), CVE-2025-15566 (auth-proxy-set-headers), CVE-2026-1580 (auth-method), CVE-2026-24513 (auth-url) and CVE-2026-3288 (rewrite-target). Through the snippets, CVE-2021-25742 obtained all Secrets in the cluster from an Ingress alone.
Fix: Remove the annotation (move the behaviour into the application or the controller's own configuration); if it must stay, run a fixed controller release with --enable-annotation-validation, keep allow-snippet-annotations false and annotations-risk-level at High or below in the controller ConfigMap, and plan the move to a Gateway API implementation, since ingress-nginx is retired.		highaudit / networkCM-7 Least Functionality, SI-2 Flaw Remediation, SC-7 Boundary Protection
KN-N010ingress-nginx ConfigMap widens what an Ingress may ask of the controller
The controller ConfigMap decides which annotations an Ingress may use. allow-snippet-annotations: true re-enables the snippet annotations through which CVE-2021-25742 read every Secret in the cluster (the feed's fix is to set it to false); annotations-risk-level: Critical accepts the Critical-risk annotations, which the default High refuses; strict-validate-path-type: false drops the path validation added for CVE-2022-4886.
Fix: Set allow-snippet-annotations: "false" (the default), leave annotations-risk-level at High (the default) and strict-validate-path-type: "true" (the default) in the ingress-nginx controller ConfigMap, or remove the keys.		highaudit / networkCM-6 Configuration Settings, CM-7 Least Functionality, SI-2 Flaw Remediation
KN-N011Ingress path type ImplementationSpecific on ingress-nginx
CVE-2026-24512 (ingress-nginx before v1.13.7 and v1.14.3): a rules.http.paths.path value injected nginx configuration into the controller, which can read every Secret in the cluster. Before upgrading, the advisory's mitigation is a validating admission controller that rejects Ingress resources with the ImplementationSpecific path type, the one path type whose paths ingress-nginx does not validate. An Ingress that names no class is served by the cluster's default IngressClass, which may be ingress-nginx (not on OpenShift, whose router serves it).
Fix: Use pathType Prefix or Exact (ingress-nginx validates those paths when strict-validate-path-type is true, the default), and run ingress-nginx v1.13.7, v1.14.3 or later; a regular-expression path (use-regex) can only be ImplementationSpecific, so upgrade before keeping one. Plan the move to a Gateway API implementation.		highaudit / networkSI-2 Flaw Remediation, SI-10 Information Input Validation, CM-7 Least Functionality
KN-N012NetworkPolicy selects no pod in this bundle
A NetworkPolicy applies only to the pods its podSelector selects. One that selects none of the namespace's pods (often a label typo) protects nothing, while the namespace still looks covered (KN-N001 passes): the pods it was written for accept traffic from every pod.
Fix: Make spec.podSelector match the pod template labels of the workloads the policy is for (or use podSelector: {} for every pod in the namespace).		mediumaudit / networkSC-7 Boundary Protection, SC-7(5) Boundary Protection | Deny by Default — Allow by Exception, AC-4 Information Flow Enforcement
KN-S001Privileged container
A privileged container has full access to the host (all devices, all capabilities). On OpenShift it is rejected unless the ServiceAccount is granted the 'privileged' SCC.
Fix: Remove securityContext.privileged; grant only the specific capability required.		criticalaudit / securityAC-6 Least Privilege, CM-7 Least Functionality, SC-39 Process IsolationPrivileged Container
KN-S002Privilege escalation not disabled
Required by the Pod Security 'restricted' profile; prevents setuid binaries from gaining privileges. OpenShift's restricted-v2 SCC (default for new 4.11+ installs) defaults it to false and rejects an explicit true; clusters upgraded from 4.10 or earlier may still admit pods under the legacy 'restricted' SCC.
Fix: Set securityContext.allowPrivilegeEscalation: false on every container.		mediumaudit / securityAC-6 Least Privilege, AC-6(10) Least Privilege | Prohibit Non-privileged Users from Executing Privileged Functions, CM-7 Least FunctionalityContainer with privilege escalation allowed
KN-S003Container may run as root
Running as UID 0 widens the impact of a container breakout. On OpenShift the restricted-v2 SCC assigns an arbitrary non-root UID, so images must also work as a random UID in group 0.
Fix: Set runAsNonRoot: true (pod or container securityContext) and build images with a non-root USER.		mediumaudit / securityAC-6 Least Privilege, CM-6 Configuration SettingsDocker CIS 4.1: Ensure That a User for the Container Has Been Created
KN-S004Fixed UID/fsGroup conflicts with OpenShift restricted-v2 SCC
restricted-v2 uses MustRunAsRange for UIDs and MustRunAs for fsGroup: pods requesting IDs outside the namespace's openshift.io/sa.scc.uid-range / supplemental-groups annotations are rejected ('unable to validate against any security context constraint').
Fix: Remove runAsUser/fsGroup and let OpenShift assign IDs from the namespace range; keep runAsNonRoot: true. If a fixed UID is truly required, bind the ServiceAccount to the nonroot-v2 SCC. (runAsGroup is not governed by SCCs and is left alone.)		highaudit / platformCM-6 Configuration Settings, AC-6 Least Privilege
KN-S005Dangerous Linux capabilities added
Capabilities like SYS_ADMIN or NET_ADMIN are near-root and enable container escapes.
Fix: Remove the capability; the Pod Security 'restricted' profile only allows adding NET_BIND_SERVICE.		highaudit / securityAC-6 Least Privilege, CM-7 Least FunctionalityCAP_SYS_ADMIN capability added
KN-S006Capabilities not dropped
Pod Security 'restricted' requires dropping ALL capabilities. OpenShift restricted-v2 drops them for you, the legacy 'restricted' SCC (clusters upgraded from <=4.10) does not.
Fix: Set securityContext.capabilities.drop: ["ALL"].		lowaudit / securityAC-6 Least Privilege, CM-7 Least FunctionalityDrop All Capabilities
KN-S007Writable root filesystem
A read-only root filesystem blocks tampering and many post-exploitation techniques.
Fix: Set readOnlyRootFilesystem: true and mount emptyDir volumes for paths the app writes (e.g. /tmp).		lowaudit / securityCM-7 Least Functionality, SI-7 Software, Firmware, and Information IntegrityContainer using read-write root filesystem
KN-S008Seccomp profile not set to RuntimeDefault
Pod Security 'restricted' requires RuntimeDefault or Localhost seccomp; Unconfined disables syscall filtering. OpenShift restricted-v2 applies RuntimeDefault by default. A Localhost profile must name its file: an empty localhostProfile is the CVE-2023-2431 pattern, which kubelets before v1.24.14, v1.25.10, v1.26.5 and v1.27.2 ran without any seccomp filter.
Fix: Set securityContext.seccompProfile.type: RuntimeDefault at pod level.		lowaudit / securityCM-6 Configuration Settings, CM-7 Least Functionality, SC-39 Process IsolationDocker CIS 5.21: Ensure the default seccomp profile is not disabled
KN-S009Host namespaces shared
Sharing host namespaces exposes host processes and network; OpenShift requires a privileged/hostnetwork SCC.
Fix: Remove hostNetwork/hostPID/hostIPC unless this is a node agent that truly needs it.		highaudit / securitySC-39 Process Isolation, AC-6 Least PrivilegeDocker CIS 5.9 and 5.20: Ensure that the host's network namespace is not shared, Docker CIS 5.15: Ensure that the host's process namespace is not shared, Docker CIS 5.16: Ensure that the host's IPC namespace is not shared
KN-S010hostPath volume
hostPath mounts let a container read or modify the node filesystem; container runtime sockets give full node takeover.
Fix: Replace hostPath with a PVC, emptyDir, ConfigMap/Secret or a CSI ephemeral volume.		highaudit / securityAC-6 Least Privilege, SC-39 Process IsolationMounting Sensitive Host Directories, Mount Container Runtime Socket
KN-S011hostPort used
hostPort binds directly on the node, bypasses NetworkPolicy expectations and limits scheduling.
Fix: Expose the container through a Service instead of hostPort.		mediumaudit / securitySC-7 Boundary Protection, CM-7 Least Functionality
KN-S012Mutable image reference
':latest' or untagged images change underneath you, break rollbacks and defeat image scanning/signing.
Fix: Pin an explicit version tag, ideally an immutable digest (image@sha256:...).		mediumaudit / supply-chainCM-2 Baseline Configuration, SI-7 Software, Firmware, and Information IntegrityLatest tag
KN-S013Secret value hard-coded in environment
Literal credentials in manifests leak through Git history, `oc get -o yaml`, logs and audit trails.
Fix: Move the value to a Secret and reference it with valueFrom.secretKeyRef (or an external secret store).		highaudit / secretsIA-5(7) Authenticator Management | No Embedded Unencrypted Static Authenticators, SC-28 Protection of Information at RestEnvironment Variable Contains Secret
KN-S014ServiceAccount token automounted
A mounted token turns any RCE into authenticated Kubernetes API access.
Fix: Set automountServiceAccountToken: false on the pod (or ServiceAccount) unless the app calls the API.		lowaudit / securityAC-6 Least Privilege, IA-5 Authenticator Management, CM-7 Least FunctionalityPod Service Account Token Automatically Mounted
KN-S015RBAC wildcard grants
Wildcards grant every current and future resource/verb, including secrets and escalation paths.
Fix: Enumerate the exact apiGroups, resources and verbs needed.		highaudit / rbacAC-3 Access Enforcement, AC-6 Least Privilege
KN-S016Binding to cluster-admin
cluster-admin is full control of the cluster.
Fix: Bind a narrowly scoped Role instead; cluster-admin should only be held by break-glass identities.		criticalaudit / rbacAC-6 Least Privilege, AC-6(5) Least Privilege | Privileged Accounts
KN-S017RBAC privilege-escalation paths
These permissions let a subject obtain more privileges than it was granted. Only the StatefulSet and DaemonSet controllers need to write ControllerRevisions (the built-in edit and admin roles do not grant it): with write access to StatefulSets too, CVE-2026-2270 (kube-controller-manager up to v1.34.11, v1.35.8, v1.36.4 and v1.37.0) let a namespace user create pods in other namespaces.
Fix: Remove escalate/bind/impersonate, cluster-wide secret reads, nodes/proxy, pod exec, ephemeral containers, ControllerRevision writes and workload creation unless essential; where they are, enforce Pod Security restricted in that namespace, and run kube-controller-manager v1.34.12, v1.35.9, v1.36.5, v1.37.1 or later.		highaudit / rbacAC-3 Access Enforcement, AC-5 Separation of Duties, AC-6 Least Privilege
KN-S018Secret material committed in manifests
base64 is an encoding, not encryption.
Fix: Deliver secrets with an external secret store (External Secrets Operator, Vault, AWS Secrets Manager on ROSA) or Sealed Secrets; never commit base64 'data' to Git.		mediumaudit / secretsIA-5(7) Authenticator Management | No Embedded Unencrypted Static Authenticators, SC-28 Protection of Information at Rest
KN-S019Permissive SecurityContextConstraints
A permissive SCC bound to a ServiceAccount defeats OpenShift's default pod isolation.
Fix: Prefer the built-in restricted-v2 / nonroot-v2 SCCs; custom SCCs must not allow privileged, host namespaces, host directories or RunAsAny UIDs.		highaudit / securityAC-6 Least Privilege, CM-7 Least Functionality, SC-39 Process Isolation
KN-S020Unmasked /proc
Unmasked /proc exposes host kernel interfaces.
Fix: Remove securityContext.procMount: Unmasked.		highaudit / securitySC-39 Process Isolation, CM-7 Least Functionality
KN-S021gitRepo volume
gitRepo volumes are deprecated since Kubernetes 1.11, off by default from 1.33 (GitRepoVolumeDriver feature gate) and gone after 1.35. CVE-2024-10220 (CVSS 8.1; kubelet, fixed in v1.28.12, v1.29.7, v1.30.3 and v1.31.0) let a user who can create a pod run commands outside the container through a gitRepo volume, and CVE-2025-1767 (every version, no fix) lets a pod read local git repositories on the node through one.
Fix: Clone with an init container into an emptyDir volume that the app container mounts (the replacement the Kubernetes docs give), and remove the gitRepo volume.		highaudit / securitySI-2 Flaw Remediation, CM-7 Least Functionality, SC-39 Process Isolation
KN-S022Pod sysctl name or value contains '+' or '='
CVE-2022-0811 ('cr8escape', CRI-O 1.19 to 1.24.0, fixed in 1.19.6, 1.20.7, 1.21.6, 1.22.3, 1.23.2 and 1.24.0) passed a sysctl whose value carried '+' to set kernel.core_pattern and escape the container with root on the node; OpenShift's container runtime is CRI-O, and the GitHub advisory names an admission webhook that denies pods with a '+' in a sysctl value as the mitigation.
Fix: Remove the sysctl, or write it as one plain name and one plain value (a sysctl never needs '+' or '=' in either); on OpenShift keep to the safe sysctls or the ones a Tuned profile allows.		highaudit / securitySI-2 Flaw Remediation, SC-39 Process Isolation, CM-7 Least Functionality
KN-S023Container workingDir under /proc
CVE-2024-21626 ('Leaky Vessels', CVSS 8.6; runc 1.0.0-rc93 to 1.1.11, fixed in 1.1.12) let a container whose working directory was under /proc/self/fd/ start with a working directory in the host filesystem through a leaked file descriptor: a container breakout to the host filesystem. The advisory's mitigation is to permit only a process.cwd of / and to deny working directories under /proc.
Fix: Set workingDir to a directory that exists in the image (/app, /opt/app-root) or leave it unset, and run nodes with runc 1.1.12 or later.		highaudit / securitySI-2 Flaw Remediation, SC-39 Process Isolation
KN-S024ingress-nginx controller image below the fixed releases
The controller image tag is a release; the Kubernetes CVE feed names the releases that fix each ingress-nginx CVE. CVE-2025-1974 (CVSS 9.8, fixed in v1.11.5 and v1.12.1) gives anyone on the pod network code execution in the controller through its validating admission webhook; the later fixes close configuration injection through annotations and paths (CVE-2025-15566 in v1.12.5/v1.13.1; CVE-2026-1580, CVE-2026-24512, CVE-2026-24513 and CVE-2026-24514 in v1.13.7/v1.14.3; CVE-2026-3288 in v1.13.8/v1.14.4/v1.15.0; CVE-2026-4342 in v1.13.9/v1.14.5/v1.15.1).
Fix: Run a release that fixes every advisory below (v1.13.9, v1.14.5, v1.15.1 or later), disable the validating webhook (--validating-webhook) until the controller is at least v1.11.5 or v1.12.1, and plan the move to a Gateway API implementation: the project is retired and fixes nothing found after its last release.		highaudit / supply-chainSI-2 Flaw Remediation, SA-22 Unsupported System Components
KN-S025volumeMount subPath carries shell or PowerShell characters
CVE-2023-3676 (CVSS 8.8; kubelet up to v1.24.16, v1.25.12, v1.26.7, v1.27.4 and v1.28.0, fixed in v1.24.17, v1.25.13, v1.26.8, v1.27.5 and v1.28.1): on Windows nodes kubelet put a pod's subPath into a PowerShell command, so anyone who could create a pod ran commands as SYSTEM on the node. The fix passes the path in an environment variable; the feed names pod create events with embedded PowerShell commands as the sign of exploitation. A subPath is a path inside the volume and never needs these characters.
Fix: Use a plain relative path for subPath (letters, digits, '-', '_', '.', '/'), and run Windows nodes with kubelet v1.24.17, v1.25.13, v1.26.8, v1.27.5, v1.28.1 or later.		highaudit / securitySI-2 Flaw Remediation, SI-10 Information Input Validation, SC-39 Process Isolation
KN-S026Credential stored in a ConfigMap
A ConfigMap does not provide secrecy or encryption: it is not covered by encryption of Secrets at rest, and the built-in view role reads ConfigMaps but not Secrets, so everyone with read access to the namespace reads the credential. Flags a key that names a credential with a literal value, a URL with a password, a private key, an access key id or a token in any value, and a password=... or token: ... line in a config file value.
Fix: Move the value into a Secret (created outside Git: an external secret store or Sealed Secrets) and mount or reference it; in a Helm chart, render credentials into a Secret template, never into a ConfigMap.		highaudit / secretsIA-5(7) Authenticator Management | No Embedded Unencrypted Static Authenticators, SC-28 Protection of Information at Rest
KN-S027Legacy ServiceAccount token Secret
A Secret of type kubernetes.io/service-account-token is a legacy mechanism that holds a long-lived, non-expiring ServiceAccount token; the Kubernetes docs say to create one only when the TokenRequest API cannot be used and the exposure of a non-expiring token in a readable API object is acceptable. Anyone who can read Secrets in the namespace can act as that ServiceAccount until the Secret is deleted.
Fix: Delete the Secret and get short-lived tokens instead: a projected serviceAccountToken volume in the pod, or the TokenRequest API (kubectl create token) for a client outside the cluster.		mediumaudit / secretsIA-5 Authenticator Management, AC-6 Least Privilege
KN-S028RBAC binding grants a role to everyone
The Kubernetes RBAC good practices ask to review bindings for the system:unauthenticated group and remove them, as they give access to anyone who can contact the API server at a network level. system:authenticated is every user and every ServiceAccount token in the cluster (a token stolen from any pod works), and system:serviceaccounts every ServiceAccount of every namespace. The built-in bindings (system: names, label kubernetes.io/bootstrapping: rbac-defaults) are left alone.
Fix: Bind the role to the ServiceAccounts, users or groups that need it, never to system:unauthenticated, system:anonymous, system:authenticated or system:serviceaccounts.		highaudit / rbacAC-14 Permitted Actions Without Identification or Authentication, AC-3 Access Enforcement, AC-6 Least Privilege
KN-ST001ReadWriteMany requested from a ReadWriteOnce-only StorageClass
The provisioner cannot satisfy RWX, so the PVC stays Pending (ProvisioningFailed).
Fix: Use a shared-filesystem class: efs-sc (AWS EFS CSI) on ROSA/EKS, ocs-storagecluster-cephfs (ODF) or NFS on OpenShift on-prem, azurefile-csi on Azure. gp3-csi/gp2-csi (EBS) are block volumes and only support ReadWriteOnce.		highaudit / storageCM-6 Configuration Settings
KN-ST002ReadWriteOnce volume shared by a rolling Deployment
A RWO volume attaches to one node. Extra replicas or surge pods scheduled elsewhere hang in ContainerCreating with 'Multi-Attach error for volume'.
Fix: Use a StatefulSet with volumeClaimTemplates, strategy: Recreate with replicas: 1, or a RWX class if the app supports concurrent writers.		highaudit / storageCM-6 Configuration Settings, CP-10 System Recovery and Reconstitution
KN-ST003Zonal storage with Immediate volume binding
Immediate binding may create the volume in a zone where the pod cannot run, leaving it Pending.
Fix: Set volumeBindingMode: WaitForFirstConsumer so the volume is created in the zone the pod is scheduled to.		mediumaudit / storageSC-36 Distributed Processing and Storage, CM-6 Configuration Settings
KN-ST004EFS StorageClass is missing required parameters
Dynamic provisioning with the AWS EFS CSI driver uses access points and needs the file system id.
Fix: Set parameters.provisioningMode: efs-ap and parameters.fileSystemId: fs-xxxxxxxx (plus directoryPerms).		highaudit / storageCM-6 Configuration Settings
KN-ST005PVC has no storage request
The API server rejects PersistentVolumeClaims without a storage request.

KN-ST006PersistentVolume path carries command or traversal characters
CVE-2023-5528 (CVSS 7.2; kubelet from v1.8.0, fixed in v1.25.16, v1.26.11, v1.27.8 and v1.28.4): on Windows nodes the in-tree storage plugin ran a local PersistentVolume path as part of a command, so a user who could create pods and PersistentVolumes got admin rights on the node; the feed names PersistentVolume create events with local path fields containing special characters as the sign of exploitation. CVE-2026-3864 (csi-driver-nfs before v4.13.1) and CVE-2026-3865 (csi-driver-smb before v1.20.1): a '../' in the subDir of a volume identifier made the driver delete directories outside the share; the advisories say to look for traversal sequences in the volumeHandle of PersistentVolumes using these drivers.
